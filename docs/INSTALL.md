# 安装、使用与维护

一个仓库、一份插件。`scripts/install.py` 是首次安装时运行的宿主机工具，不是第二个插件，也不会成为额外常驻服务。QQ 指令、网页后台、静态帮助图和安装工具都随同下载、统一更新。

## 先确认环境

| 场景 | 操作 |
|---|---|
| 空白服务器 | 先安装并连接 TRSS＋NapCat，登录 QQ；群管不代装框架、Redis、NapCat 或登录账号 |
| Linux＋Docker Compose，TRSS 源码绑定到宿主机目录 | 推荐安装向导；需要宿主机 Git、Python 3.9+、Docker Compose 和现有目录及 Docker 管理权限 |
| Linux 普通安装 | 向导可复制完整插件、创建默认配置；重启仍使用机器人原有命令，不猜测 systemd/PM2 服务 |
| Windows 普通安装 | Git/ZIP 安装后运行 `python scripts/install.py --trss "实际TRSS目录"`，再按原方式重启；Node 20+ 和 TRSS 依赖须预先可用 |
| Docker Desktop、命名卷/镜像内源码、docker run、host 网络、复杂 Compose YAML | 使用本页手动安装；不会尝试给容器提权或猜测重建参数 |
| 其他机器人框架 | 目前未提供接入层，不能直接使用；独立插件不代表跨框架免适配 |

运行向导前确认 NapCat 已连接 TRSS；向导的网页检查不能证明 QQ 已在线。禁言、踢人等需要 QQ 中机器人本身有管理权限。

普通安装应使用原来管理 TRSS 的账号运行；Linux 新建插件目录继承 plugins 目录的属主，原有文件不会重新改属主。网页若已有自定义启动环境变量，沿用原端口；默认地址不代表已经验证。

## 从下载到第一次回复

### 方法一：快捷安装

在 Linux **宿主机**终端运行 README 的一条快捷命令。它下载官方 `main` 的干净临时克隆，运行工具后清理本次临时克隆；不会通过执行 Git 自动钩子安装服务。快捷脚本需要 curl、Git、Python 3.9+ 已安装，不能直接执行一次 git clone 就触发自动部署。

不想直接执行远程脚本时，可先下载、阅读，再运行：

```sh
curl -fsSLo groupguard-install.sh https://raw.githubusercontent.com/719083594/GroupGuard-Plugin/main/scripts/install.sh
less groupguard-install.sh
bash groupguard-install.sh
```

### 方法二：Git/ZIP 下载完整插件

先进入实际 TRSS 根目录，确认尚无目标目录：

```sh
git clone https://github.com/719083594/GroupGuard-Plugin.git plugins/GroupGuard-Plugin
python3 plugins/GroupGuard-Plugin/scripts/install.py --trss "$PWD"
```

Docker 用户必须在宿主机操作绑定挂载的源码目录，不能在 `docker exec` 打开的终端里运行向导。若使用 ZIP，将内容放到相同目录，再运行其中的工具；不需要安装另一个包或运行 `npm install`。不要用下载包覆盖现有 `config/local.json`、`data/`。

有多个机器人时，向导让你选编号；无人值守时必须用 `--container` 或 `--trss` 指定。工具只搜索当前目录、有限父目录、常见目录和运行容器的绑定挂载，不扫描整个磁盘。自定义目录找不到时显式填写路径。

工具不更改已有源码。重复运行会检查配置并再次使机器人加载插件，可能短暂中断机器人回复；普通更新不必重跑安装向导。

### 手动配置主人

编辑安装结果给出的 `config/local.json`，只修改现有 `masters` 数组，保留其余字段：

```json
"masters": ["123456789", "234567890"]
```

以上是合成示例，替换成负责人的真实 QQ，数字要放在引号内。文件中还有其他字段，不要把这一行当作完整 JSON 覆盖整个文件。配置按后续请求读取，无需为改主人再次重启。主人可执行高权限维护操作；安装工具和网页都不自动写入或更换主人，没有添加主人的聊天指令。

普通命令认可 TRSS `isMaster === true` 或此名单；自动退群的主人豁免只读此名单。默认主人数组为空且启动时提示，不会自动抄入 TRSS 主人。主人身份不能代替机器人实际的 QQ 群权限。

### QQ 中启用与验证

在目标群由群主或机器人主人依次发送：

```text
#群管开启
#群管帮助
#群管状态
#群管今日榜
```

帮助默认图片；状态默认图片，可用 `#群管状态 文字` 查纯文字。榜单只统计实际收到并记录的消息，新安装没有历史记录是正常情况。默认启用统计与撤回能力，点赞、欢迎、离群通知、定时日报和审核策略仍按各自开关配置；不会因安装就自动审批或退群。全部指令及权限见 [README](../README.md)。

## 打开网页

向导验证成功后，会输出实际宿主机端口，优先 15083，自动选择范围到 15103；端口只绑定 `127.0.0.1`。同一台服务器上的浏览器可直接打开该地址；自己的电脑需要 SSH 隧道。

在**自己电脑**的终端执行，替换用户名和服务器地址；目标端口使用安装日志中的实际端口：

```sh
ssh -N -o ExitOnForwardFailure=yes -L 127.0.0.1:36083:127.0.0.1:15083 用户名@服务器公网地址
```

SSH 如需密码，在终端中输入；首次主机指纹应按服务器真实信息核对。保持这个终端打开，浏览器访问 `http://127.0.0.1:36083/`。首次登录密码在服务器插件目录 `data/admin-initial-password.txt`，请自己在服务器终端读取，不发到聊天或截图。首次登录强制改密，之后初始密码文件删除；已有管理密码不重置。

例如在插件目录读取初始密码：

```sh
cat data/admin-initial-password.txt
```

文件不存在且以前已改密时，使用现有密码，不要删除 `admin-auth.json` 来重置。密码遗失需另行核实身份并处理，不包含在安装工具的自动操作中。

可给向导添加 `--ssh-target ubuntu@server.example.com`，生成不含密码的连接命令和插件 `data/install/open-admin.cmd`。使用文件传输工具把它下载到 Windows 电脑后双击，建立 SSH 连接后手动打开上述浏览器地址。它使用你电脑原有的 OpenSSH 登录方式，不包含密钥、密码、不自动放行主机指纹；不保证所有 SSH 自定义端口/跳板机布局免配置。自定义 SSH 参数可在个人电脑的 SSH 配置中维护。

网页可编辑本群、全局策略、账号安全，以及按机器人＋群隔离的新闻来源和 Key。主人 QQ 不在网页修改。保存后后续请求读取新配置，关闭网页不影响运行。新闻 API/Key 只通过网页设置，不能发到 QQ 指令或公开仓库。

## 参数与只读检查

在已下载的插件目录运行：

```sh
python3 scripts/install.py --help
python3 scripts/install.py --check --trss /opt/TRSS-Yunzai
```

`--check` 只识别安装目标，不写配置、不安装、不重启，也不宣称端口或 QQ 已通过验证。

| 参数 | 用途 |
|---|---|
| `--trss 路径` | TRSS 在宿主机上的目录，路径有空格时用引号 |
| `--container 名称` | 多个运行机器人各自挂载独立源码时明确选择容器；共用同一源码目录会被拒绝 |
| `--native` | 明确为普通安装，跳过 Docker 查询；Docker 无权限时不自动把容器的宿主机源码误认成普通安装 |
| `--env-file 路径` | 原 Compose 使用自定义环境文件时填写，可重复并保持原顺序 |
| `--port 数字` | Docker 的宿主机回环端口；已有不同映射时不强制替换 |
| `--ssh-target 用户@主机` | 生成自己电脑的连接说明和可选 Windows 入口，不接收密码 |
| `--no-restart` | 只安装、配置并留记录，不重启。若修改了 Docker 环境/端口，之后须按记录的原 Compose 命令重新创建机器人，单纯 restart 不会应用新映射 |
| `--no-web` | 安装 QQ 插件，不修改 Docker 网页配置；不关闭插件原有管理服务，默认仍在其本机地址监听 |
| `--check` | 只识别，优先于安装操作 |

安装向导不会自动安装 Git、Python、Docker、Node，不添加其他插件、全局定时任务或系统服务。实际运行只由 TRSS 加载，Python 只在你执行安装工具时使用。

## Docker 自动配置范围

先核对现有 Compose/.env 能否重现运行容器的配置哈希；不一致就停止，防止安装群管时顺便应用用户尚未部署的其他改动。使用原来的自定义环境文件、原 Compose 版本重试，或先自行处理原有变更。

对于常见的块式 YAML，工具只更新目标服务的三项 `GROUPGUARD_ADMIN_*` 变量，增加一条固定的宿主机回环端口映射。不会将整个 Compose 渲染成含秘密的固定 JSON；保留原变量引用和无关内容。用 `docker compose config --format json` 再核对，除上述项目外有任何语义变化就不应用。多文件 Compose 仅在最后文件有可识别的目标服务块时自动处理；锚点、行内对象或特殊写法可能要求手动操作。

应用前，原文件备份到本插件 `data/install/时间戳/compose.before`，执行阶段和文件哈希写到同处 `state.json`。备份可能包含部署凭据，文件仅当前用户可读，不能上传 GitHub。不会将安装记录放在其他项目目录；唯一外部持久修改是原 Compose 文件。

修改后仅执行原 Compose 项目的目标服务：

```sh
docker compose up -d --no-deps --no-build --pull never 实际机器人服务名
```

工具实际附加原来的项目目录、项目名、Compose 文件和环境文件参数；不要省略这些参数照抄去操作其他项目。已有端口和环境已经一致时，仅重启选中的现有容器。不会执行 `down`、删除卷、拉镜像、构建、重启 NapCat/Redis。启动后检查管理页和未登录 `/api/config` 的 401 响应；仍需 QQ 里实测帮助和状态图。

已有自定义容器内管理端口时不自动覆盖，可使用 `--no-web` 保留现状。多个运行容器共用同一 TRSS 源码目录时拒绝自动安装，因为同一个插件 data 不能由多个进程同时写入；不能只选一个容器就假定数据已经隔离。

容器运行用户的 Node 必须至少 20；工具核对宿主机/容器用户映射，并检查插件配置可读、config/data 可写。不能确定用户映射、源码只读或不支持的宿主机布局时停止，不用 `chmod 777` 绕过。

### 手动配置 Docker 网页

自动识别不支持的布局按 README 的 Docker 配置，将环境变量和回环端口合并到原服务，再按原来的完整 Compose 命令仅重新创建机器人。`docker run` 用户应保留原容器完整参数、挂载和恢复条件，添加对应环境与 `-p 127.0.0.1:15083:15083` 后由自己按原方式替换机器人容器；工具不会猜参数自动删除旧容器。

host 网络模式无需发布端口，使用插件默认 `127.0.0.1` 监听，再建立 SSH 隧道。镜像内源码/命名卷可手动将完整插件放到 TRSS 的 plugins 目录，并确保重建容器后仍保留；建议先确认数据持久化，工具不会为了安装改变现有卷。

## 常见问题与恢复

| 提示或现象 | 处理 |
|---|---|
| 找不到 TRSS | 在宿主机运行，填写真实 `--trss`；未挂载源码、未运行容器或特殊布局按手动安装 |
| 多个机器人 | 明确选择，不自动修改全部机器人 |
| Compose 与运行容器不一致 | 核对原 `.env`、`--env-file`、Compose 版本和已有未应用改动；不要使用强制覆盖 |
| 不支持 YAML 写法 | 原配置未改，按手动说明补齐环境和端口 |
| 管理端口被占用 | 查看日志实际选择的端口，或用 `--port` 指定空闲端口；不终止占用程序 |
| 本机 36083 被占用 | 修改 SSH `-L` 左侧端口，并在浏览器使用新的本地端口 |
| 权限不足 | 使用原来管理该机器人的账号或管理员权限；不把 Docker socket 挂进机器人容器 |
| 网页已通，QQ 没回复 | 确认 TRSS 加载日志、NapCat/QQ 在线、本群已开启、调用人权限和指令；网页响应不代表 QQ 在线 |
| 安装中断或命令超时 | 先看 `data/install/时间戳/state.json`、当前容器、Compose 文件和网页；命令可能已执行，不连续重试 |
| 安装锁存在 | 确认对应安装进程是否仍在运行，结束/完成后再处理遗留锁；不自动删除来绕过并发保护 |

恢复只处理本次安装修改，不清空插件数据。需要恢复 Compose 时，先比较当前文件哈希与 `state.json` 的 `patchedSha256`；有其他人后续修改就先人工合并，不能直接覆盖。确认仍是本次写入版本后，将 `compose.before` 复制回 `state.json` 的 `file` 路径，保持原权限，再使用记录中的原 Compose 命令、`up -d --no-deps --no-build --pull never 服务名` 仅重新创建机器人。`state.json` 不包含密码，但备份文件应保密。工具超时后不自动回滚，以免把已成功运行的容器再次改变。

原配置、数据与管理密码始终保留。不要因为插件没加载而删除 `data/` 或写入锁；先确认旧 TRSS 进程是否真正退出，再按其日志处理异常残留。

## 更新、迁移与卸载

Git 安装在插件目录执行：

```sh
git pull --ff-only origin main
```

也可由主人私聊发送 `#群管更新`；仅官方 origin/main、干净源码和快进更新受支持，成功后重启 TRSS。ZIP 安装用新发布包手动更新公开文件，保留 `config/local.json`、`data/` 和其他实例文件。普通更新不必重新运行安装向导。首次修改 Docker 端口或环境变量才需要重建容器，日常仅重启机器人。

迁移前停好旧实例，备份完整插件目录，尤其是配置、data 中统计/待审/额度/认证，以及原 Compose/.env。敏感备份不要公开上传；同一运行数据不能同时由两个进程写。新服务器的 QQ 登录、TRSS/NapCat 和真实群权限另行准备。

卸载前停止 TRSS 并备份插件的配置和 data；移走 `plugins/GroupGuard-Plugin` 整个目录，再按原方式启动机器人。若要完整关闭管理映射，只移除原 Compose 中群管专用环境变量和端口，再仅重新创建机器人；保留其他插件和服务。不要用历史 `compose.before` 覆盖期间新增的无关配置。工具未添加额外系统服务或定时任务，无需到其他位置寻找第二个插件。
