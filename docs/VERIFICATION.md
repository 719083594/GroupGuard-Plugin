# GroupGuard 2.0.1 验证范围与复核方法

文档整理日期：2026-11-01（Asia/Shanghai）。

本文件记录检查方法和证据边界，**不预填尚在执行中的全量测试数量，也不把模拟通过写成真实平台通过**。发布矩阵固定为 Node 20/22/24/26 × Linux/Windows，八项均须通过；最终本地执行结果由同一份源码的实际命令退出状态、测试摘要和检查记录确认。CI 矩阵已配置也不表示每个环境已经运行。

## 2.0.1 状态图片验收

本版新增状态默认 PNG、图片失败退文字，以及 `#群管状态 文字` 和 `/群管状态 文字` 的纯文字路径。按“本地检查与 README 核对 → GitHub 八项 CI → 东京部署与实机核验”的顺序推进；本节不预先填写最终测试数量、CI 或部署结论。

| 项目 | 本版需要保留的证据 |
|---|---|
| 状态数据与权限 | 使用合成对象核对卡片与文字取同一份查询数据；群管理员/群主/主人权限不变，关闭本群仍可查状态 |
| 默认图片 | 合成数据生成有效 PNG，实际目视检查文字、布局和裁切；不能只凭图片魔数或渲染函数返回成功 |
| 失败与强制文字 | 图片渲染或发送失败仍可取得文字；“状态 文字”跳过渲染；不改变配置或执行额外管理动作 |
| 帮助资源 | 两张 JPEG 和来源清单更新至 2.0.1；状态说明与 README、实际入口一致 |
| 发布与实机 | 新提交对应八项 CI 均通过后再部署；部署后另行确认 QQ 收到 PNG，强制文字返回文字 |

## 本地可重复检查

在插件目录执行：

```sh
npm test
npm run check:manifest
```

`npm test` 通过 `scripts/test.mjs` 显式枚举顶层 `tests/*.test.mjs`，不递归扫描临时副本和备份；无需 shell 展开通配符。测试使用合成账号、模拟 OneBot/新闻请求器、模拟时钟、临时状态、隔离 Git 仓库和临时环回管理 HTTP 服务，不向真实 QQ 群执行操作。

Windows 沙箱如限制系统临时目录，可将本次测试临时文件放在插件自己的 `.test-tmp/`：

```powershell
New-Item -ItemType Directory -Path .test-tmp -Force | Out-Null
$env:TEMP = (Resolve-Path .test-tmp).Path
$env:TMP = $env:TEMP
npm test
npm run check:manifest
```

该目录仅存本地检查产物，不进入 Git 或发布包。不要把实例 `config/local.json`、`data/` 放入测试夹具，也不要为测试清空真实配置或状态。

| 检查层 | 主要文件或操作 | 能证明什么 |
|---|---|---|
| 命令解析 | `command.test.mjs` | 新入口与指定简写、拒绝旧名/全角/群卫、引用与裸词边界 |
| 核心行为 | `core.test.mjs`、`behavior.test.mjs`、`edge-cases.test.mjs` | 权限、目标保护、审核、通知、统计、失败/未知分流与数据保留的模拟结果 |
| 配置与新闻 | `config-news.test.mjs` | 迁移与精确机器人/群隔离、聊天不可绕过、Key 保留/替换/清空、请求鉴权和脱敏的模拟结果 |
| 状态与点赞 | `state-likes.test.mjs` | 预算持久化、跨群/并发/重启、失败和未决、迁移当日保守处理 |
| TRSS 接入 | `integration.test.mjs` | 实际导入 `index.js`，用 PluginBase 路由模拟核查主人、事件、去重及真实 OneBotAdapter 代码路径 |
| 管理 HTTP/API | `admin.test.mjs` | 临时实例的登录、强制改密、会话/CSRF/Origin、只读主人、Key 回读、配置保存与 revision 冲突、1 MiB 请求上限及大名单保存 |
| 管理界面逻辑 | `admin-ui.test.mjs` | 表单覆盖、输入校验、强制改密控制、重复/未决写入保护、Key 三态保存和 A/B 对象绑定；DOM 表面模拟不证明真实浏览器布局 |
| 帮助资源 | `help-images.test.mjs` | 本地图片读取、公开/主人页、无 AI 依赖、格式/哈希/路径/大小及文字降级 |
| 状态卡片 | 状态图片专项检查及核心/接入回归 | 合成状态的 PNG 与文字数据一致、强制文字、权限及图片失败降级；不证明 QQ 已收到 |
| Git 更新 | `update.test.mjs` | 隔离仓库中的快进、来源/分支/脏树/分叉拒绝、保护实例数据及失败处理 |
| 声明同步 | `npm run check:manifest` | 静态声明与当前命令/配置定义一致；不证明外部管理程序已接入 |
| 离线演示 | `node scripts/readme-demo.mjs` | 本地模拟核心生成有效字段示例和权限拒绝，输出离线 HTML；不启动服务 |

只运行测试文件的一部分时，应明确列出文件；不能据局部摘要称“全部验收通过”。修改代码后需要按受影响范围重新检查，最终全量摘要对应最终提交或交付副本。

## 静态资源与打包检查

帮助 JPEG 的代码校验和目视检查分别记录；哈希有效不证明图片文字、排版和权限说明正确。发布包应携带公开图、主人图、清单和制作模板；日常用户无需重新渲染帮助。状态 PNG 按查询生成，须另用合成状态目视检查和对应渲染/失败回归验证，不能用帮助 JPEG 通过来代替。

可在本地审阅 npm 打包清单，不连接外部服务：

```sh
npm pack --dry-run --json --ignore-scripts --offline
```

清单须包含源码、默认配置、独立声明、静态帮助资源、`resources/admin/` 三个界面文件与必要测试；不得包含 `config/local.json`、`data/`（包括管理密码哈希、初始密码文件）、`.test-tmp/`、实例 Key、账号数据、备份或私有验证材料。npm 清单不代替 GitHub ZIP/Release 的实际内容检查；不同打包方式分别确认。

## 仍需真实环境验证

| 外部项目 | 本地检查的限制 | 对应真实验收 |
|---|---|---|
| TRSS＋NapCat 加载 | PluginBase 模拟不是实际框架加载 | 在目标运行环境核对 apps、事件、账号适配、主人及权限 |
| QQ 帮助图/状态图/消息 | 本地图片有效不证明 QQ 已收到或展示正常 | 在明确授权的测试场景核对帮助 JPEG、状态 PNG 及状态强制文字的送达与展示 |
| 新闻 API | 模拟请求器不能证明供应方鉴权或当前返回结构 | 使用实际来源核对鉴权、图片/文字输出与耗时，保护 Key |
| 浏览器管理界面 | API/DOM 模拟不证明实际页面操作和布局 | 在合成实例检查登录、强制改密、群/全局/新闻保存、Key 保留/替换/清空、冲突和退出；真实实例首次密码由用户自行更换 |
| GitHub 更新 | 隔离 Git 仓库不能证明实际网络或远端状态 | 在适用 Git 安装中核对官方来源、快进和重启提示 |
| Node/操作系统矩阵 | 配置 CI 不代表 CI 已执行 | 分别保留实际 Node 版本、操作系统及命令结果 |
| 服务器部署 | 本地副本完成不代表服务器已变更 | 获得对应部署授权后，核对实际版本与主流程 |

自动化检查不通过对真实成员禁言、踢人、审批、退群或点赞来代替模拟；获得具体授权后的真实群联调另记时间、版本、操作及平台结果，不把本地通过当成部署成功。等待外部输入的项目保持待验证，不计入已通过结果。

旧版 v1.0.x 曾记录过本地/服务器检查和旧独立 HTTP 模式实测；2.0.0 已有的检查见上面的历史基线。它们都不覆盖 2.0.1 的本次变更，不能证明当前服务器已经升级。本文件不沿用旧版本测试数量作为新版本结论。
