# GroupGuard-Plugin · 群管

GroupGuard 2.0.0 是由 **TRSS 加载、通过 NapCat OneBot v11 接口执行操作**的独立插件。成员管理、入群审核、通知、统计、新闻和点赞都在同一插件内，内部模块不需要另装插件。核心要求 Node.js 20+，无额外 npm 或数据库依赖；实际 TRSS 环境还须满足其自身运行要求。

## 安装与首次配置

在 TRSS 根目录执行：

```sh
git clone https://github.com/719083594/GroupGuard-Plugin.git plugins/GroupGuard-Plugin
```

也可将 ZIP 发布包解压到 `plugins/GroupGuard-Plugin`，使该目录直接包含 `index.js`、`lib/`、`package.json`。按平时方式重启机器人，加载时会创建 `config/local.json`。接入账号必须提供 `bot.sendApi(action, params)`；只支持 TRSS＋NapCat。独立接收 OneBot 事件的旧 HTTP 运行模式已移除，浏览器配置使用插件内置的本机管理服务。

**请先手动填写插件主人。** 编辑插件的 `config/local.json`，只修改已有的 `masters` 字段，保留其他设置。例如以下格式支持多个负责人 QQ，数字仅为示例，使用时换成实际账号：

```json
"masters": ["123456789", "234567890"]
```

`masters` 是整个插件的高权限身份，可修改全局设置、群名单和更新源码；没有添加或更换主人的聊天指令。普通命令同时认可 TRSS 的布尔 `isMaster` 和插件 `masters`，但**自动退群的主人豁免只读插件 `masters`**，不会自动导入 TRSS 主人名单。未填写时启动日志会提示；默认名单为空，公开源码不含真实主人账号。

默认所有群 `enabled=false`，邀请审核 `inviteMode=off`。由群主或主人在目标群发送 `#群管开启`，再发送 `#群管帮助`。主人身份不代替机器人实际 QQ 群权限。

## 浏览器配置

插件加载后默认在 `http://127.0.0.1:15083` 提供中文管理界面。首次密码位于插件 `data/admin-initial-password.txt`，在该机器的终端中读取后登录；页面会强制先修改初始密码，新密码至少 12 个字符。修改后所有旧会话退出，使用新密码重新登录，初始密码文件会删除。管理密码与插件主人 QQ 是两种独立身份。

侧栏提供“本群设置”“新闻来源”“全局设置”和“账号安全”。可选择已连接机器人或手填未在线账号，添加/移除群配置，直接用表单编辑开关、审核、名单、通知和定时参数，无需抄写完整 JSON。名单和答案一行一项。页面只显示插件主人是否已配置，不显示主人 QQ，也不能更换 `masters`。

新闻来源按具体机器人＋群保存，不支持通配账号。切换配置对象会加载该对象的完整来源；新对象会清空接口与鉴权，不能把 A 群的接口套用到 B 群的 Key。鉴权支持 none、Bearer、自定义请求头和查询参数。原 Key 只显示“已配置”，保存时明确选择保留、替换或清空；编辑其他字段不会清掉 Key。

保存时会校验配置版本；若其他窗口或聊天已修改配置，页面提示重新加载，不自动覆盖。超时或断网导致保存结果未知时，也先重新加载核对，不自动重复写入。密码和 Key 不写入页面本地存储、地址栏或控制台；退出后清空页面里的配置和敏感输入。关闭浏览器不影响插件使用已保存配置运行。

| 管理服务环境变量 | 默认与用途 |
|---|---|
| `GROUPGUARD_ADMIN_ENABLED` | 未设置时开启；设为 `0` 关闭管理服务，群管仍运行 |
| `GROUPGUARD_ADMIN_HOST` | `127.0.0.1`；Docker 容器内可设 `0.0.0.0` |
| `GROUPGUARD_ADMIN_PORT` | `15083` |

远程服务器可用 SSH 将管理端口映射到本机，例如把下面的用户名和服务器替换为实际值：

```sh
ssh -N -L 36083:127.0.0.1:15083 用户@服务器
```

随后浏览器访问 `http://127.0.0.1:36083`。Docker 如需发布此端口，在容器设置 `GROUPGUARD_ADMIN_HOST=0.0.0.0`，宿主映射使用 `127.0.0.1:15083:15083`；通过本机或 SSH 隧道访问，不公开暴露管理端口。改变监听环境变量后重启机器人。

## 升级到 2.0.0：不兼容变更

- 主人继续手填 `config/local.json` 的 `masters`；TRSS 主人不会自动成为自动退群豁免名单，浏览器也不开放主人编辑。
- 帮助、榜单、裸“赞我”和引用裸“撤回”采用下表的新入口；移除群卫、全角前缀、裸群管帮助、旧榜单、带前缀点赞和兼容加群审核入口。
- 移除离群自动拉黑、定时全体禁言/解禁和独立 OneBot HTTP 运行模式；手动管理、现有名单和统计等数据保留。
- 新增受登录保护的浏览器配置界面；新闻 API/Key 只能在浏览器中按机器人与群维护，旧全局来源按可确认的既有对象迁移，不再聊天修改。
- 旧安装无法证明当天完整点赞提交次数时，迁移当天暂停新增，次日使用持久额度；不通过清空旧记录重置上限。

## 指令

下表的 `#群管…` 正式指令均支持对应半角 `/群管…`；参数和权限相同。正文去除首尾空白。群管理或统计命令只在相应群使用，普通成员不能借主人指令绕过核心权限检查。

| 功能 | 指令 | 权限与条件 |
|---|---|---|
| 帮助 | `#群管帮助`、`#群管帮助 文字` | 所有人；不要求开启本群 |
| 版本 | `#群管版本` | 所有人；不要求开启本群 |
| 本群开关 | `#群管开启`、`#群管关闭` | 群主或主人 |
| 状态 | `#群管状态` | 群管理员、群主或主人 |
| 本群配置 | `#群管设置 <字段> <值>` | 群管理员、群主或主人；本群已开启 |
| 成员黑名单 | `#群管黑名单`；后接 `添加 <QQ>` 或 `删除 <QQ>` | 群管理员、群主或主人 |
| 成员白名单 | `#群管白名单`；后接 `添加 <QQ>` 或 `删除 <QQ>` | 群管理员、群主或主人 |
| 单人禁言 | `#群管禁言 @成员 [时长]` | 群管理员、群主或主人；机器人须管理权限 |
| 单人解禁 | `#群管解禁 @成员` | 同禁言 |
| 踢出成员 | `#群管踢 @成员` | 双方管理权限和目标保护；不永久拒绝再次申请 |
| 全体禁言/解禁 | `#群管全体禁言`、`#群管全体解禁` | 双方相应管理权限 |
| 管理员任免 | `#群管设管理 @成员`、`#群管撤管理 @成员` | 操作人须群主或主人；机器人须群主 |
| 专属头衔 | `#群管头衔 @成员 <头衔>` | 同管理员任免；头衔 1—30 字符 |
| 引用撤回 | 引用后 `#群管撤回`，或引用后裸 `撤回` | 群管理权限、有效本群引用及目标校验 |
| 批量撤回 | `#群管撤回 @成员 [条数]` | 默认 1 条，受条数/历史窗口限制 |
| 发言榜 | `#群管今日榜`、`#群管昨日榜`、`#群管月榜` | 本群开启、`statistics` 开启 |
| 新闻 | `#群管日报` | 本群开启并配置本群来源 |
| QQ 点赞 | 裸 `赞我` | 群内，本群开启、`likes` 开启，额度未满 |
| 待审列表 | `#群管待审核` | 已开启的本群/管理群中，按管理权限和可见范围检查 |
| 审核同意/拒绝 | 引用通知后 `#群管同意` / `#群管拒绝`，或后接 `<请求编号>` | 按请求、通知位置和权限判断；主人、指定私聊审核用户及允许的邀请人按相应范围处理 |
| 全局配置 | `#群管全局 <字段> <值>` | 仅主人私聊 |
| 群黑白名单 | `#群管群黑名单`、`#群管群白名单`；后接 `添加 <群号>` 或 `删除 <群号>` | 仅主人私聊 |
| 维护 | `#群管日志`、`#群管更新日志`、`#群管更新` | 仅主人私聊；操作日志最近 20 条 |

`@成员` 可按原规则换为数字 QQ。禁言、解禁还保留 `禁言 @成员 [时长]`、`解禁 @成员`、`#禁言`、`/禁言`、`#解禁`、`/解禁`。时长支持数字、中文数字及秒、分、分钟、时、小时、天；纯数字按分钟，默认 10 分钟，范围 1 秒至 30 天。

裸 `撤回` 必须带有效群消息引用；无引用、私聊或“撤回一下”等正文不执行。裸 `赞我` 必须整条正文精确匹配，“快来赞我”不触发。其他功能不因此支持裸词。

成员管理操作核查操作人、机器人和目标的真实角色；身份查询失败不按有权限处理。不能普通禁言/踢机器人自身、操作人、群主或管理员；撤管理、头衔按各自允许范围处理。引用撤回另行校验：只处理本群，撤回他人消息须机器人管理权限且目标为可确认普通成员；撤回机器人自己消息不要求机器人管理员，操作人仍要有管理权限。

批量撤回只覆盖插件收到的近期 ID，不下载完整群历史。近期记录最多 500 条、最长 120 分钟；实际筛选受 `recallLimit` 和 `recallWindowMinutes` 约束，QQ 平台限制仍有效。逐条执行后汇总成功与失败，不把失败写成成功。

2.0 不再接受所有“群卫”别名、全角 `＃`/`／`、裸 `#群管`/`/群管`、`#确认加群`/`#拒绝加群`、旧发言日榜/月榜名称、任何带前缀的“赞我”。这些入口不回复停用提示；普通消息记录和统计仍按原规则处理。

## 本群与全局设置

设置热读取，保存前检查类型、范围、时区和字段组合；验证失败保留有效文件。布尔值支持 `开/关`、`开启/关闭`、`true/false`、`1/0`；整数、`HH:mm` 时间和 JSON 数组分别使用对应格式。

| 本群字段 | 默认值与规则 |
|---|---|
| `enabled` | false；聊天只用开启/关闭指令调整 |
| `statistics` / `recall` / `likes` | true / true / false，仍受总开关限制 |
| `rankLimit` | 10，范围 1—50 |
| `recallLimit` / `recallWindowMinutes` | 20 条 / 10 分钟，范围 1—50 / 1—120 |
| `welcomeEnabled` / `leaveEnabled` | false / false |
| `welcomeMessage` / `leaveMessage` | 支持 `{userId}`、`{groupId}`、`{name}`，最多 2000 字符 |
| `dailyEnabled` / `dailyTime` | false / `08:00` |
| `joinMode` | `off`、`manual`、`answer`、`accept`、`reject`；默认 off |
| `question` / `answers` / `exactMatch` | 问题提示 / 答案数组 / false；两种匹配均忽略英文大小写 |
| `minLevel` | 0 关闭，范围 0—200；查真实 QQ 等级，未知转人工 |
| `blackUsers` / `whiteUsers` | 成员 QQ 数组，黑名单优先；每项名单最多 5000 人 |

答案最多 100 项，每项非空且最多 200 字符；`question` 最多 2000 字符。答案审核至少有一个答案；问题提示不修改 QQ 平台入群问题。成员黑名单仅用于准入，不屏蔽整个机器人，也不自动处理已在群成员。

| 全局字段 | 默认值与规则 |
|---|---|
| `masters` | []；只在文件手动维护，不能聊天修改 |
| `managementGroups` / `notifyUsers` | [] / []；管理群、额外私聊通知和审核用户 |
| `inviteMode` | 默认 `off`；支持 off/manual/accept/reject |
| `allowInviterConfirm` / `allowAdminInvite` / `notifyInviter` | 默认均 false |
| `requestExpireMinutes` / `maxPendingRequests` | 5 分钟 / 20 项；范围 1—60 / 1—100，队列为整个实例共用 |
| `blackGroups` / `whiteGroups` | 群号数组，每项最多 5000；邀请审核黑名单优先 |
| `autoQuitEnabled` / `minGroupMember` / `autoQuitTime` | false / 10 人 / `00:00`；人数范围 1—10000 |
| `autoQuitMessage` | 支持 `{memberCount}`、`{minMember}`、`{groupIds}`，最多 2000 字符 |
| `timezone` | `Asia/Shanghai`；统计日期、额度及调度共用 |
| `groups` | 结构化群配置数组，最多 1000 项；不能聊天整体替换 |
| `newsSources` | 浏览器按精确机器人＋群维护；不能聊天设置 |
| `schemaVersion` / `legacy` | 内部迁移信息，不是可聊天设置字段 |

`groups` 每项通过 `botId`、`groupId` 定位。具体账号配置优先于 `botId:"*"`；普通设置不能改身份字段，创建专用群配置不影响其他账号，新闻凭据不随通配群配置自动复制。

```text
#群管设置 welcomeEnabled 开
#群管设置 welcomeMessage 欢迎 {userId} 加入本群！
#群管设置 recallLimit 10
#群管设置 answers ["答案一","答案二"]
#群管设置 joinMode answer
#群管全局 inviteMode manual
```

`autoBlacklistOnLeave`、`scheduledMute`、`muteTime`、`unmuteTime` 已移除，旧值不能重新启用自动拉黑或定时全体禁言/解禁；已有名单和手动指令保留。通用字段设置使用明确白名单，不能修改未知旧键、主人、新闻凭据或内部迁移对象。

## 审核、通知和自动退群

开启人工邀请审核前，请配置管理群或私聊通知用户。成员申请还通知目标群。正式审核绑定机器人、请求 flag、通知 ID 和实际通知位置；不能凭引用文字伪造权限。群内在该请求真实通知过的群检查审核人角色；私聊按主人、指定审核用户及允许的原邀请人判断。

重复申请及并发审核防重，平台结果未知先核验，不自动重复操作。明确失败的人工审核保留待审记录。过期只清理插件待审，不自动拒绝平台申请；满队列提示人工处理。未提供好友申请处理。

欢迎和离群通知各自可选。自动退群指机器人退出，默认关闭，不解散群：入群事件由全局开关控制，每日巡检只查已配置且开启的群。先检查白名单、管理群、插件主人所在群、机器人群主等豁免，再判断黑名单/人数条件；邀请审核与退群的优先级不同。退群提示失败不继续退出。用户已处理的 TRSS 冲突功能保持现状。

## 统计、新闻与点赞

统计按机器人、群、成员隔离，排除本机器人；保留今日/昨日及当前月/上个月，每张表最多 5000 人。文字榜单显示发言数和图片数；短期历史用于去重，不宣称完整历史去重。关闭统计仍保存撤回所需近期消息 ID，其他业务不以统计为前置条件。

新闻 `#群管日报` 与定时推送使用同一份本群来源，支持图片或文字，10 秒超时、文字最多 4000 字符。停机错过不补发，失败当天不自动重试；需要当天内容可手动查询。内容由实际接口提供，不自动生成或保证主题筛选。

`newsSources` 按精确机器人、群保存 `url`、可选 `key`、`authType`、`authName`，支持 none/bearer/header/query 鉴权。浏览器“新闻来源”表单只回读是否已有 Key，保存区分保留/替换/清空，不把遮掩文本当新 Key。通用聊天指令不能修改 API/Key，也不能通过嵌套对象绕过。插件运行不依赖浏览器页面在线；凭据不进入回复、状态、日志或发布包。

点赞仅在群内裸发 `赞我`：每机器人、每个配置时区自然日最多调用 `send_like` 10 次，每次 `times:10`，即总提交额度 100 赞，所有群共用，最多涉及 10 人。发送前持久预留，已经发出的失败/超时也占额，不按实际到账退还。当天向同一人已经发出请求后不重复提交；未决不补发，重启不清额度。旧安装不能证明当天完整提交次数时，迁移当天保守暂停新增点赞，次日启用新账本；旧成功记录为空也不能认定是新安装，因为旧失败调用可能未记成功。只有确实全新安装才直接启用新账本。

以上防重复和迁移规则是控制提交量的保守实现，不能保证到账 100 赞或账号免风控。额度只约束本插件同一持久状态写入者，不统计其他插件/人工点赞；同账号跨服务器运行须另有共享协调，不能宣称独立实例天然共用额度。

## 静态帮助图

`resources/help/` 的公开图、主人图及 `manifest.json` 随 Git/ZIP 发布包提供，属于长期静态资源。群管直接读取，不依赖 AI-Plugin、模型、浏览器或实时渲染；启动和重启不重画、不删除。群内只发公开页，主人私聊才附主人页；读图或校验失败退文字，`#群管帮助 文字` 直接使用文字路径。

帮助内容变化时，开发者在制作阶段借用 TRSS 内置渲染器生成 JPEG，再保存并提交图片及清单。制作入口为 `scripts/render-help.mjs`；日常用户无需运行制作脚本。图片最多 8 页、每页最多 2 MiB，并核对格式、路径与哈希，不能读取其他插件文件。

## 更新与数据保护

主人私聊 `#群管更新` 仅支持官方 `origin` 为 `https://github.com/719083594/GroupGuard-Plugin.git`、当前 `main` 的 Git 克隆安装。只对官方 `origin main` 执行快进拉取；脏源码、分叉、错误来源、异常分支或 merge/rebase/冲突时停止。不 reset、clean、stash，不覆盖实例配置或数据，不自动重启。超时先核对实际提交状态；完成后提示重启生效。

ZIP 安装请手动替换新发布包，保留 `config/local.json`、`data/` 及其他实例配置；不会伪称 Git 更新成功，也不提供自动解压覆盖。配置和运行数据必须保持未被 Git 跟踪；静态帮助资源随版本正常更新。

## 开发与验证

```sh
npm test
npm run manifest
npm run check:manifest
```

`npm test` 通过 `scripts/test.mjs` 显式枚举 `tests/*.test.mjs`，不递归扫描临时副本或备份，并兼容 Windows 与 Node 20。测试采用合成账号、模拟 OneBot/时钟、隔离 Git 仓库和临时本机管理服务，不向真实群执行平台操作。`tests/integration.test.mjs` 实际导入 TRSS 入口，以 PluginBase 路由模拟验证接入；`tests/admin.test.mjs` 检查管理 HTTP/API，`tests/admin-ui.test.mjs` 检查表单、强制改密、Key 操作、版本冲突与配置对象隔离。它们不能代替真实 TRSS/NapCat、浏览器页面、新闻鉴权和 QQ 收图的对应联调；实际执行结果见 [验证范围](docs/VERIFICATION.md)。

`plugin.manifest.json` 是独立插件声明，包含完整命令、权限上下文、配置字段和敏感标志，由管理程序主动读取；不包含实例秘密，不依赖另外安装统计/新闻/点赞插件。修改命令或默认配置后运行声明生成与一致性检查。核心 Node 20/22/24 的自动检查与实际 TRSS 运行环境分别判断。

功能目标见本地重构规格；来源说明保留在 [NOTICE.md](NOTICE.md)。发布只包含源码、默认配置、声明、帮助模板及成图和必要测试，不包含实例配置、运行状态或私有验证材料。
